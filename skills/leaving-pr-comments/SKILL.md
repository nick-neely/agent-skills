# Leaving PR Comments

1. **Confirm intent and target.** Post only when the user's request or active workflow authorizes it. Verify the PR, thread, diff side and current line as applicable. A review request alone does not authorize publishing review comments.
2. **Write the response.** Lead with the conclusion. Cite the code, behavior, check, reproduction or fix commit that supports it. Distinguish observed facts from judgment and deferral from implementation. Keep the response concise and useful to the reviewer. Project instructions govern attribution and signatures.
3. **Preview.** Check the full Markdown, quotes and attachments for secrets or private context. Preserve literal content with a structured tool argument or body file. Verify quoting and blank lines.
4. **Post and verify.** Submit once. Read back the saved comment or review and retain its URL. If a request times out, check whether it succeeded before retrying. Resolve a review thread only after the explanation was saved successfully and its finding is accounted for. Leave disputed or blocking feedback open.
